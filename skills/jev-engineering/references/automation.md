# JEV 辅助的自动化闭环

将 JEV 用作低延迟语义判断层，而不是权限系统、状态机或执行器。一个可靠闭环必须保持 `observe → decide → policy → act → verify`，不能从模型选择直接跳到未约束执行。

## 五阶段闭环

1. **Observe**
   - 重新采集当前状态，并归一化为小而充分的 state：任务、可见文本、候选控件、状态版本、会话/窗口身份与必要几何信息。
   - 将页面文本视为不可信数据；去除与决策无关的噪声，并在外发前脱敏。

2. **Decide**
   - 代码先过滤不可行项、枚举有限候选并计算确定性特征；JEV 只在候选中排序或分类。
   - 候选集包含 `WAIT`、安全导航、`HANDOFF` 等非控件动作，避免模型被迫误选可见控件。
   - 完成判据必须是可观测后置条件，不是对目标的重复。

3. **Policy**
   - 在模型之外用确定性策略检查任务范围、允许动作、副作用类型、数据边界、风险级别、预算和速率限制。
   - 模型置信度只决定自动化或升级路由，不能覆盖 deny/allow 规则、用户授权或 checkpoint。

4. **Act**
   - 执行前检查状态版本与引用仍新鲜；失效时重新 Observe，不使用旧坐标。
   - 每次只做一个最小动作，记录 action key、前置条件、期望后置条件、超时和重试语义。

5. **Verify**
   - 动作后重新观测，验证期望后置条件、未预期副作用和任务进度。不得以 API 返回成功代替状态验证。
   - 相同状态与相同动作重复出现时停止重试，升级给 System-2 或人工。

## 多速率调度

- **快环**：确定性传感、反抖、假设检查和实时控制；不在每帧调用 JEV。
- **语义环**：在状态转换、新弹窗、新候选集或事件边界调用 JEV。
- **慢环**：多步规划、新异常、长时无进展、范围变更或高风险决策交给 System-2/人工。

各环应有独立的频率、截止时间和失败预算。优先由事件和状态指纹触发，而不是无条件轮询。

## Shadow-first 与渐进放量

1. 先只观察和记录：生成建议动作，但不执行。
2. 将建议与人工/现有系统结果对比，按场景评估正确率、误放行、误拦截、校准度和延迟。
3. 先开放只读且可逆动作，再按任务族逐步放量；高风险动作保留 checkpoint。
4. 模型、提示、观测器或阈值变更后重新跑 shadow/golden set，不沿用旧校准结论。

## 幂等动作与稳定引用

- 优先使用“设为目标值”而非“切换”；执行前读当前值，执行后验证目标值。
- 为外部写操作使用幂等键。只自动重试明确幂等的动作；结果不明时先查询，不盲目重发。
- 引用应基于平台原生 ID/语义属性、会话与窗口身份、可见性、几何和状态版本，而不是长列表下标。
- 点击前重新解析引用并校验语义；若多个节点匹配或页面已变，不猜测。

## 硬安全策略与接力

确定性策略至少应覆盖：任务级 allowlist、永不自动的动作类别、收件人/账号/环境绑定、数据外发限制、金额/频率/步数/时间预算、机密脱敏和不可逆操作 checkpoint。页面文本或 JEV 输出不能修改这些策略。

升级包应包含：原始目标与授权、当前状态和新鲜度、已执行动作及验证结果、当前候选与 JEV 分数、触发 checkpoint 的原因、可安全继续的探针，以及回滚/恢复信息。交给人工或 System-2 后，除非得到新决定，不要在后台继续执行。
